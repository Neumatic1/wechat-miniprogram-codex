# GitHub 项目精选小程序需求分析

更新日期：2026-05-20

## 1. 项目背景

GitHub 上每天都会出现大量增长迅速、质量较高的开源项目。普通开发者很难持续追踪近期热门项目，也很难在短时间内判断一个项目是否值得进一步了解、收藏或使用。

本项目希望做一款“GitHub 项目精选”微信小程序，每天更新近期热门开源项目，并用中文整理每个项目的用途、亮点和适用场景，帮助用户快速完成项目发现和初步筛选。

## 2. 要解决的问题

- 用户不知道每天有哪些值得关注的新兴或快速增长开源项目。
- GitHub 项目介绍通常以英文为主，用户需要额外花时间阅读 README、仓库描述和文档。
- 仅看 star 数无法判断项目近期热度、实际用途和适用人群。
- 热门项目分布在不同语言、主题和领域中，缺少适合移动端快速浏览的中文摘要。

## 3. 目标用户

- 希望跟踪开源趋势的开发者。
- 需要寻找技术选型参考的工程师、架构师、技术负责人。
- 关注 AI、前端、后端、工具链、数据、运维等领域新项目的技术内容创作者。
- 想快速了解 GitHub 热门项目但英文阅读成本较高的学习者。

## 4. 核心使用场景

- 用户每天打开小程序，查看今日精选热门项目列表。
- 用户通过日榜、周榜、月榜快速查看不同周期内增长最快的项目。
- 用户进入项目详情，阅读中文介绍，理解项目用途、亮点、适用场景和仓库基础信息。
- 用户收藏感兴趣的项目，之后继续查看。
- 用户复制项目原始 GitHub 链接，在外部浏览器或 GitHub 客户端中进一步研究。

## 5. MVP 范围

MVP 阶段优先完成“发现项目”和“快速理解项目”的闭环。

必要功能：

- 热门项目榜单：日榜、周榜、月榜。
- 项目详情页。
- 中文项目摘要。
- 项目基础信息展示：名称、作者、描述、语言、star 数、fork 数、今日或近期增长、GitHub 链接。
- 榜单切换：支持日榜、周榜、月榜切换。
- 收藏功能：优先使用本地收藏，暂不强制登录。
- 允许复制 GitHub 原始仓库链接。
- 加载、空状态、错误状态。

## 6. 暂不开发的功能

- 用户账号体系与云端同步收藏。
- 评论、点赞、社区讨论。
- 复杂推荐算法和个性化推荐。
- 项目对比、评分体系、排行榜历史趋势图。
- 订阅消息推送。
- 付费功能。
- 小程序内直接调用大模型 API。

## 7. 内容生成与数据来源初步判断

热门项目数据需要微信云开发云函数定时抓取、整理和缓存，不应由小程序前端直接请求 GitHub 或大模型服务。

MVP 明确使用云开发云函数作为后端。后端负责：

- 定时获取 GitHub 仓库数据。
- 计算日榜、周榜、月榜的 star 增长。
- 调用大模型自动生成中文项目摘要，并将摘要结果入库。
- 向小程序提供结构化榜单和项目详情接口。

初步可选数据来源：

- GitHub Search API：可按创建时间、更新时间、star 数等条件搜索项目。
- GitHub Trending 页面或第三方趋势数据：适合发现日榜、周榜项目，但稳定性和合规性需要确认。
- 自建定时任务：每天拉取候选项目，计算增长指标，再生成中文摘要。

中文摘要生成在云函数中完成，并保存结构化结果。小程序前端只消费已经整理好的项目数据。

star 增长基线采用快照方式存储：

- 云数据库保存仓库基础信息表和 star 快照表。
- 每次采集时记录仓库当前 star 数、采集时间和仓库标识。
- 日榜按当前快照与约 24 小时前快照差值计算。
- 周榜按当前快照与约 7 天前快照差值计算。
- 月榜按当前快照与约 30 天前快照差值计算。
- 快照建议至少保留 45 天，便于月榜计算和异常追溯。

## 8. 关键产品决策

- MVP 先做“日榜/周榜/月榜 + 详情中文介绍 + 收藏”，避免过早加入账号体系和复杂推荐。
- 热门榜单按 star 增长判定：日榜看 24 小时增长，周榜看 7 天增长，月榜看 30 天增长。
- 日榜每天更新两次，降低数据滞后感；周榜和月榜可跟随采集结果同步刷新。
- MVP 暂不做语言、技术方向或综合标签分类，先用榜单周期切换作为主筛选方式。
- 列表应服务于快速浏览，不把 README 长文搬到首页。
- 详情页应回答三个问题：这个项目是什么、解决什么问题、适合谁使用。
- 收藏先本地化，降低登录和隐私合规成本。
- 中文摘要无需显式标注“AI 生成”或“人工整理”。
- 首版界面语言为中文；这指小程序 UI、按钮、提示、摘要内容优先使用中文，不限制被收录的 GitHub 项目必须是中文项目。
- 敏感能力和密钥只放在后端或云函数，不放在小程序前端。

## 9. 已确认问题

- 热门口径：按 star 增长生成日榜、周榜、月榜。
- MVP 需要后端服务，不只做静态 mock 数据。
- 分类维度：暂不做语言、技术方向或综合标签分类。
- 中文摘要：不需要标注 AI 生成或人工整理。
- GitHub 链接：MVP 先支持复制原始仓库链接。
- 首版语言：小程序界面和整理内容以中文为主，但收录项目不限中文项目。

## 10. 已确认技术口径

- 后端形态：微信云开发云函数。
- 数据采集频率：日榜每天更新两次。
- star 增长基线：使用云数据库快照表保存历史 star 数，通过当前快照与历史快照差值计算日榜、周榜、月榜。
- 中文摘要生成方式：云函数调用大模型自动生成后入库。
- GitHub 链接方式：MVP 先支持复制链接，不做 web-view 打开。
