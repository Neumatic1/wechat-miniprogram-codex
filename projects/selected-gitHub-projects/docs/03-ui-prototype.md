# GitHub 项目精选小程序 UI 原型

更新日期：2026-05-20

## 1. 设计目标

MVP UI 以“快速扫读、快速理解、快速保存”为核心。用户打开小程序后，应能立刻看到近期增长最快的 GitHub 项目，并在不阅读完整 README 的情况下理解项目用途。

界面风格应简洁、克制、偏工具型，适合开发者高频浏览。首版不做复杂视觉包装，不做营销首页，不做分类筛选。

## 2. 页面清单

- 榜单页：首页，展示日榜、周榜、月榜。
- 项目详情页：展示单个项目的中文介绍和仓库信息。
- 收藏页：展示本地收藏项目。

## 4. 全局导航结构

建议使用底部 tab：

- `榜单`：默认入口。
- `收藏`：用户保存的项目。

项目详情页作为二级页面，从榜单页或收藏页进入，不放在底部 tab 中。

## 5. 榜单页原型

### 5.1 页面目标

让用户快速浏览当前周期内 star 增长最快的项目，并能进入详情或收藏项目。

### 5.2 页面布局

从上到下：

1. 顶部标题区。
2. 榜单周期切换区。
3. 更新时间提示。
4. 项目列表。
5. 加载、空状态或错误状态。

### 5.3 信息结构

顶部标题区：

- 主标题：`GitHub 项目精选`
- 副信息：`发现近期增长最快的开源项目`

榜单周期切换区：

- 使用分段控件样式。
- 三个选项：`日榜`、`周榜`、`月榜`。
- 默认选中 `日榜`。
- 切换后刷新列表，并保留明确的选中状态。

更新时间提示：

- 文案示例：`日榜更新于 05-20 12:00`
- 位置靠近榜单切换区下方。
- 字号弱于项目标题，不抢占主视觉。

项目卡片：

- 排名：`#1`、`#2`、`#3`。
- 仓库名：例如 `owner/repo`。
- 中文一句话简介。
- 主要语言。
- 当前 star 数。
- 当前周期增长数，例如 `+1,248 stars`。
- 收藏按钮。

### 5.4 项目卡片布局

推荐卡片内信息顺序：

1. 第一行：排名、仓库名、收藏按钮。
2. 第二行：中文一句话简介，最多展示两行。
3. 第三行：语言、star 总数、周期增长数。

卡片点击区域：

- 点击卡片主体进入详情页。
- 点击收藏按钮只触发收藏或取消收藏，不进入详情。

### 5.5 主要交互

- 切换 `日榜 / 周榜 / 月榜`：展示当前榜单加载状态，请求成功后替换列表。
- 下拉刷新：刷新当前选中的榜单。
- 点击项目卡片：进入项目详情页。
- 点击收藏按钮：切换收藏状态，并使用 toast 提示。

### 5.6 状态设计

加载中：

- 首次进入时展示列表骨架屏。
- 切换榜单时可保留旧列表并在顶部或列表区展示轻量加载状态。

空状态：

- 文案：`当前榜单暂无数据`
- 辅助文案：`稍后再来看看新的热门项目`
- 操作：`重新加载`

错误状态：

- 文案：`榜单加载失败`
- 辅助文案：`可能是网络或服务暂时不可用`
- 操作：`重试`

## 6. 项目详情页原型

### 6.1 页面目标

帮助用户在短时间内理解项目是什么、解决什么问题、适合什么场景，并复制 GitHub 链接进一步研究。

### 6.2 页面布局

从上到下：

1. 顶部仓库信息。
2. 关键指标区。
3. 中文一句话简介。
4. 项目用途。
5. 核心亮点。
6. 适用场景。
7. GitHub 链接操作区。

### 6.3 信息结构

顶部仓库信息：

- 仓库名：`owner/repo`
- 原始描述：展示 GitHub description，最多两行。
- 收藏按钮。

关键指标区：

- star 总数。
- fork 总数。
- 当前榜单周期增长数。
- 主要语言。

中文简介：

- 展示 `summaryZh`。
- 作为详情页最重要的第一段中文内容。

项目用途：

- 标题：`这个项目做什么`
- 内容来自 `whatItDoes`。

核心亮点：

- 标题：`核心亮点`
- 使用短列表展示，建议 3 到 5 条。

适用场景：

- 标题：`适合谁使用`
- 使用短列表展示，建议 2 到 4 条。

GitHub 链接操作区：

- 展示仓库链接。
- 主操作按钮：`复制链接`。
- 复制成功后 toast：`链接已复制`。

### 6.4 主要交互

- 点击收藏按钮：收藏或取消收藏当前项目。
- 点击复制链接：调用剪贴板能力复制 `githubUrl`。
- 返回：回到来源页面，保持来源页面的榜单类型和滚动位置。

### 6.5 状态设计

加载中：

- 展示详情页骨架屏。

详情不存在：

- 文案：`项目数据暂不可用`
- 操作：`返回榜单`

摘要生成中：

- 若中文摘要为空，展示 GitHub 原始描述。
- 文案：`中文介绍生成中，稍后再来查看`

复制失败：

- toast：`复制失败，请重试`

## 7. 收藏页原型

### 7.1 页面目标

让用户快速回看自己保存的项目，并继续进入详情或复制链接。

### 7.2 页面布局

从上到下：

1. 顶部标题。
2. 收藏项目列表。
3. 空状态。

### 7.3 信息结构

顶部标题：

- 主标题：`我的收藏`
- 副信息：`本地保存，换设备后不会自动同步`

收藏项目卡片：

- 仓库名。
- 中文一句话简介。
- 主要语言。
- 收藏时 star 数。
- 取消收藏按钮。

### 7.4 主要交互

- 点击项目卡片：进入项目详情页。
- 点击取消收藏：从本地缓存移除。
- 取消成功后 toast：`已取消收藏`。

### 7.5 状态设计

空状态：

- 文案：`还没有收藏项目`
- 辅助文案：`在榜单里收藏感兴趣的项目，之后可以在这里查看`
- 操作：`去看榜单`

本地缓存读取失败：

- 文案：`收藏读取失败`
- 操作：`重试`

## 8. 核心组件说明

### 8.1 榜单分段控件

- 用于切换日榜、周榜、月榜。
- 当前选中项需要明显高亮。
- 点击后触发榜单请求。

### 8.2 项目卡片

- 用于榜单页和收藏页。
- 榜单页展示排名和周期增长。
- 收藏页不展示排名，可展示收藏状态。
- 卡片主体点击进入详情，收藏按钮单独处理。

### 8.3 指标标签

- 用于展示语言、star、fork、增长数。
- 增长数建议使用更醒目的视觉权重。
- 不使用复杂图表。

### 8.4 状态组件

- 统一处理加载、空状态、错误状态。
- 状态文案保持短句，操作按钮明确。

## 9. 用户操作路径

### 9.1 浏览并收藏项目

1. 用户打开小程序。
2. 默认进入日榜。
3. 用户扫读项目卡片。
4. 用户点击收藏按钮。
5. 页面提示收藏成功。
6. 用户进入收藏页查看已收藏项目。

### 9.2 查看详情并复制链接

1. 用户点击榜单项目卡片。
2. 进入详情页。
3. 阅读中文简介、用途、亮点和适用场景。
4. 点击 `复制链接`。
5. 页面提示链接已复制。
6. 用户到外部浏览器或 GitHub 客户端打开链接。

### 9.3 切换榜单周期

1. 用户在榜单页点击 `周榜` 或 `月榜`。
2. 页面展示加载反馈。
3. 数据返回后更新项目列表。
4. 用户继续浏览或进入详情。

## 10. 主要按钮和反馈

- `日榜 / 周榜 / 月榜`：切换榜单，选中状态高亮。
- `收藏`：收藏项目，成功提示 `已收藏`。
- `取消收藏`：取消项目收藏，成功提示 `已取消收藏`。
- `复制链接`：复制 GitHub 链接，成功提示 `链接已复制`。
- `重试`：重新请求当前页面数据。
- `去看榜单`：从收藏空状态跳转到榜单页。

## 11. 不纳入 MVP 的 UI

- 登录页。
- 语言筛选、技术方向筛选、topic 筛选。
- 趋势图表。
- 项目对比页。
- 评论或社区互动。
- GitHub web-view 内嵌页面。
- 管理后台页面。
